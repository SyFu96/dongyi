## 3. 新发现与未闭合项

### RE-M1 / MAJOR（M9）：初始化超时后允许发布/落盘，仍可能覆盖未加载的旧索引

**证据：** K:221–235、240–252、291、350–377；O:1269–1273。

`wait_init` 到500轮后直接返回，无 Ready/Timeout 结果；refresh 无条件继续。设 kb-init 的 read/JSON parse 超过约10s：refresh 读取仍为空的 Store，现存 PDF/DOCX 因无旧块被跳过，随后发布并写盘，旧缓存消失。若初始化稍后完成，还会把早先读到的旧 files/chunks 覆盖到已经刷新成功的内存状态，造成内存/磁盘/调度 done 不一致。不同结果取决于后台读和解析的位置，均不能由等待固定时长排除。kb-init spawn 返回值也被忽略；创建失败时 init_done 永远为false，每次 refresh 等10s后照样运行，search 永远空。

**必修：** 初始化未完成时 refresh 必须不发布、不持久化，返回可识别的未就绪/失败状态并保留目标重试；或者由初始化完成后触发刷新。处理 init spawn 失败，禁止当“空索引已就绪”覆盖旧盘；调度 done 只能在真正完成时更新。无需为了本复审启动产品或损坏真实索引。

### RE-M2 / MAJOR（M5+M6）：不可解析缓存在额度截断后永久丢失，且下轮错误标完整

**证据：** K:296–327、351–352、367–369；fixture K:623–635。

确定性反例：按 display 排序的 a.txt 占49999块，后面的 b.pdf 在 Python v4 里有两块 P1/P2，stamp 不变且 complete=true。第一次刷新 room=1，310–315 只保留P1，置complete=false；发布/持久化只剩P1，P2已无保留副本。删除a.txt后再次刷新：PDF complete=false，转319–327，不解析且只复用现存P1；`full=(1==1)`，又置complete=true。容量已释放，P2却永远不能补齐。room=0 时剩余PDF整份记录/块都可能丢弃，下轮被判“无缓存”永久跳过。

**必修：** 分离需要保真的不可解析源缓存与受50000额度限制的检索集合，或采用能保留源缓存的等价策略；不得以额度限制销毁唯一的PDF/DOCX缓存，不得把先前 incomplete 的短缓存误标完整。覆盖49999+2、room=0及容量释放路径。仅修complete标记无法恢复已被丢掉的块。

### RE-M3 / MAJOR（附带整改）：先删除旧 index 再 rename，并非原子替换

**证据：** K:364–375。

tmp写入成功后373主动删除index.json，374才rename。删除与rename之间进程终止会失去正式索引；rename失败时也只有tmp，read_index只认index.json，不做tmp恢复。单worker能解决两个Rust刷新互相乱序，不能消除这个文件不存在窗口，更不能保证共享索引的外部读取者一直看到有效文件。对于Rust不能重建的PDF/DOCX缓存，这会造成永久丢失。tmp写失败也没有日志或返回错误，调度仍标done，不应把统计日志当作持久化成功证据。

**必修：** 使用平台支持的替换语义，保留旧正式文件直到替换成功；失败可见且不删除旧文件。若采用恢复协议，应有完整恢复读取路径并证明不会丢唯一缓存。本项不声称做过断电实测，也不沿用上轮关于Python实际使用os.replace的未经证实描述；本次仅审查brief的原子替换承诺和当前明确的先删后改代码。

### RE-m1 / MINOR（M4）：worker spawn失败后，同目标无法重试

**证据：** O:1222–1223、1231–1245。

spawn失败留下pending=S并复位running=false。下次仍请求S，在“pending同签名”分支提前返回，不会重启worker；只有另一目标覆盖pending才可能恢复。应在判目标已排队前同时确认worker存活，或失败时清pending并保留可重试目标。正常串行调度结论不受此路径影响。

### RE-m2 / MINOR（M8）：CSV子集仍有合法记录被吞并的边界

**证据：** G:41–49。

非引号状态下任何双引号都开启引号，而标准CSV未加引号字段中的内部双引号可以是普通字符。例如 `SOH,state"of health,note\nBMS,系统\n`，会吞入后续记录直至EOF，缺失译文/第二条记录；孤立CR被直接丢弃而不结束record，`SOH,健康度\rBMS,系统\r`也被合并。多行标准引号字段及CRLF的本次指定反例已通过；这两个边界不扩展成全量CSV重审，但应补正确字段起始/换行状态或明确记录裁切。
