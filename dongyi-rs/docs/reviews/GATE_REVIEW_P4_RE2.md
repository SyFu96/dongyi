## 4. 新发现与分级

### R3／MAJOR：放弃读取失败后，补丁已丢失，界面仍可保存但保存无操作

**证据：** :1171 在 get_config 发出前清空 patches，:1172 推进代次，却未 recompute；:961–965 仅在成功响应后重算 dirty；:968 失败提示声称“草稿保留”，没有恢复补丁或重算状态；:1180 仍按 dirty 显示可点击“保存”；:1000 因 Map 为空直接返回。

确定性顺序：编辑 theme=light → dirty=true、Map 有补丁 → 点击放弃 → Map 清空，但 cfg 仍 light、dirty/dirtyRef 仍 true → get_config 拒绝 → 显示“读取配置失败（未动磁盘，草稿保留）” → 点击保存 → 空 Map 守卫直接返回，无保存请求。

实际提取函数的 Node 检查确认：cfg.theme=light、dirty=true、dirtyRef=true、patches.size=0，保存后请求数不增加。无须推测日志或 IPC 乱序即可成立。用户可重新放弃并等待成功或重新编辑恢复，但当前可见草稿不能按界面提示直接保存；构建和正常放弃实测不能排除失败分支。

此问题也意味着“dirty 一律由 patches.size 决定”尚未完全成立：放弃从清空到响应期间就存在 dirty=true／Map 为空的窗口，失败后该窗口持续存在。

**修复要求：** 放弃应在读取成功且票据有效后原子替换配置、清除补丁并 recompute；请求发出时仍推进代次使旧读取失效，但保留当前补丁直至成功。或明确实现其他完整的失败恢复方案，保证 cfg、patches、dirty/dirtyRef 同步，提示与可执行保存一致。保留期间新编辑保护；若允许放弃等待中保存，保存完成须继续使旧放弃响应失效。

**定点复验：** 放弃读取失败后草稿仍可保存；放弃等待期间新编辑不被覆盖；放弃成功后 dirty 与 Map 一致；保存中放弃仍无操作。无需全量重审。

无新增 BLOCKER。R3 是本轮唯一新增放行阻断项。
