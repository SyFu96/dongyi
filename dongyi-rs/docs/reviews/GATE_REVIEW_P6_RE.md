## 4. M3：用户文档——部分闭合，仍 FAIL

- **恢复步骤仍不够可操作。** “查看后台日志”没有说明如何取得 stderr 或现成日志位置；保存失败后的“下次成功刷新”没有说明如何确保实际重刷。orchestrator.rs:1236–1237 对同一已完成目录签名直接返回；:1300–1310 在保存失败时仍标记 done 并发完成事件。因此仅等待、同目标保存配置或同目录切换可能不会重新落盘。需说明解除权限/占用后，通过重启或切到不同有效目录再切回等方式触发实际刷新，并在允许窗口验证该恢复路径，不承诺未实现的自动保存重试。

用户可见行为表也需区分“PDF/DOCX 无既有缓存”和“有缓存但可能陈旧”；当前“始终不出现”与保留消费旧缓存的声明不一致。

闭合要求：完整限制及诊断/恢复说明同步至绿色版，补齐保留前提、实际重刷步骤和上述表格区分。无须重开 P5 已接受的算法策略。
