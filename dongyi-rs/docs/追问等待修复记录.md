# 追问长时间无回答（2026-10-15）

用户截图显示云端 `deepseek-chat` 只有问题气泡、没有回答，用户确认是等不到回答后手动停止，此前还出现过 503。

旧日志记录云端 HTTP 503，后续 HTTP 200 请求只收到多个 14 字节网络块。只凭块长度不能认定具体内容；本轮用无隐私的短请求实测，25 秒内两次收到 SSE 保活注释，没有回答正文。鉴权数据仅从本机配置读取，没有写入诊断输出。

[DeepSeek 官方说明](https://api-docs.deepseek.com/quick_start/rate_limit/)确认：请求等待调度时可能持续返回 `: keep-alive`。旧客户端每收到网络块就重新计时，保活会让“60 秒无内容超时”一直无法触发。

## 修复

- 超时按模型内容进展计时，保活注释、空行和纯角色元数据不重置时间；正文或推理增量会重置时间，推理内容不作为回答显示。
- 60 秒没有模型内容即显示超时；503 等服务异常显示可重试提示。空回答不再标记成功。
- 追问区直接显示等待、错误和重试入口；手动停止后可重试原问题，重试时替换未完成回答并重置流状态。
- 日志记录实际云端模型，分别记录失败和任务结束，避免把已处理的错误误写为成功。

云端服务的可用性由服务方决定；未更改云端/本地偏好，也未自动把问题发送到另一个后端。
